Domain 5 — Enterprise Applications, Agentic AI & Dynamic Pricing (5A)  Context-Aware Application Agent Problem  Build an intelligent, context-aware assistant that understands an entire no-code business application — its navigation hierarchy, pages, widgets, data views, filters and charts — and lets users navigate, operate and analyze it through natural language. Beyond a chatbot, the agent should determine user intent, act on the application (navigate to the right page, configure filters and UI state), retrieve and combine data, reason analytically (trends, period comparisons, likely causes) and present answers in context. Dataset Information ● Application metadata: navigation hierarchy (directories/subdirectories), page and widget catalogs, and data-view / grid / chart / filter schemas exported from the no-code platform. ● Component and UI-state definitions: available filters, date ranges, sort options, and routing / deep-link maps for each page. ● Underlying business data behind reports and dashboards (revenue, sales, operational tables) — synthetic or sample tenants where production data is sensitive. ● Natural-language request corpus: labelled user utterances mapped to the target page / report / grid and required UI state (intent and slot annotations), with example interactions. ● Public grounding and agent benchmarks as surrogates: UI / screenunderstanding corpora, text-to-SQL / NL-to-query datasets, and RAG evaluation sets. Implementation Stack Data / Metadata layer Modeling / AI Application-metadata store and a knowledge graph of pages, widgets and filters; a vector index (FAISS / Milvus / pgvector) over component descriptions; connectors to the no-code platform's APIs. LLM-based intent understanding and planning with an agent framework (LangChain / LlamaIndex, tool calling); semantic search / RAG for page and dataview retrieval; text-to-query generation; multi-step reasoning for analysis. Orchestration Actions / Agent controller with tool / function calls to navigate routes, set filters, date ranges and sorting, and read component data; browser automation (Playwright) where direct APIs are unavailable; guardrails and confirmation for state changes. Application / UX Conversational companion embedded in the app; dynamic rendering of charts, summary cards and comparisons; deep-link navigation, human-in-theloop review, and clear explanation of the actions taken. Key Performance Indicators (KPIs) ● Intent-to-destination accuracy (% of requests routed to the correct page, report, grid or dashboard). ● UI-state correctness (% of filters, date ranges and sorts configured correctly). ● Task-success rate for multi-step (agentic) requests; average steps and latency to a useful result. ● Analytical quality: correctness of trends / comparisons and explanation faithfulness (answers traceable to supporting views). ● Retrieval quality over application metadata (precision / recall, MRR) at scale — hundreds of pages and components. ● Reliability and safety: near-zero action hallucination rate, error / recovery rate, and response latency. ● User experience: task completion without manual navigation and perceived usefulness as an in-app companion.
